# 开源项目参考与本项目取舍

本项目只借鉴公开项目中的架构模式，没有复制其美术资产、地图或完整业务代码。

## SkyOffice

项目：`kevinshen56714/SkyOffice`

借鉴点：

- 交互物品显示明确的按键提示。
- 玩家进入坐下状态前先停止速度，再对齐到家具指定坐标。
- 玩家行为使用显式状态区分 IDLE、SITTING 等。
- 碰撞框位于角色脚部，而非覆盖整个精灵轮廓。
- 聊天 UI 独立于游戏画布，同时把消息显示为角色头顶气泡。

本项目的实现：

- 服务端维护沙发、床、地毯固定 anchor 和 occupancy。
- `behavior` 字段通过世界状态同步。
- 角色绘制尺寸统一，但碰撞半径只落在脚部区域。
- DOM 聊天面板与 Canvas 头顶气泡同时显示。

## Reldens

项目：`damian-pastorini/reldens`

借鉴点：

- 多人房间、聊天、玩家状态、对象与地图模块分离。
- 服务端权威处理关键状态。
- 数据库存储账号、角色与持续状态。

本项目保留轻量实现：

- Socket.IO 房间对应一个小窝。
- Node 进程内维护实时状态，SQLite 只持久化低频数据。
- 移动、碰撞、家具占用和照料请求由服务器裁决。
- 不引入 Reldens 完整的战斗、物品、NPC 或管理平台。

## Kontra

项目：`straker/kontra`

借鉴点：

- Canvas 游戏循环采用固定/受限时间步，避免页面失焦后出现巨大位移。
- 游戏渲染与 DOM UI 分离。

本项目没有将 Kontra 源码打包进来，而是以相同原则实现一个面向当前场景的小型循环，以减少生产依赖。

## 为什么 v0.2 不继续依赖 Phaser/Vite

v0.1 在服务器更新时出现过以下实际问题：

- 开发依赖被 prune 后找不到 `vite`。
- 镜像源尚未同步特定 Phaser 版本。
- 源文件更新但 `dist` 未重新构建，浏览器继续执行旧代码。

v0.2 的前端仍使用成熟的 Canvas、Socket.IO 和状态机模式，但生产构建只是静态文件复制：

```bash
npm run build
```

这使 GitHub `pull` 后的服务器更新更稳定，也便于继续替换成正式 sprite sheet 或 Tiled 地图。
